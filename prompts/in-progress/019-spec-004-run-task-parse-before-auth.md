<summary>
- The local task runner resolves GitHub App credentials only for task types that act on a repository.
- It reads the task file and derives the task type from the frontmatter before it touches credentials — the ordering the Kafka entry point does not need, because this runner has no task-type configuration field.
- A `build-fix` task run locally with no credentials reaches dispatch instead of aborting at startup.
- A `security-review` task run locally with no credentials still fails with the same credentials message.
- A task with no `task_type` still defaults to the security-review route and still requires credentials.
- The rule is a single named predicate in this runner too, so both entry points can be grepped for the same contract.
- The read → parse → resolve → dispatch order is driven by tests, not by calling the pieces in isolation.
</summary>

<objective>
Fix the second, asymmetric entry point. `cmd/run-task/main.go` has no `TaskType` field — it derives the type from the task frontmatter inside `dispatchAgent`, which `Run` calls *after* `resolveAuth`. So the same gate cannot be a one-line condition here: the task content must be read and parsed **before** credentials are resolved, and only then gated on the repo-acting set. `resolveAuth` keeps its current signature, so the reordering happens in `Run`.
</objective>

1. **Add the frozen predicate `requiresRepositoryAccess` to `cmd/run-task/main.go`** as a package-level function. It is a deliberate copy of the root `main.go` version (prompt 1) — the same name, the same sets, the same default arm — because the two files are separate `package main` binaries.

   ```go
   // requiresRepositoryAccess reports whether taskType acts on a repository and
   // therefore needs a GitHub App installation token at startup. Only
   // security-review acts on a repository; healthcheck and build-fix run without
   // GitHub credentials. An unset or unknown task type takes the stricter
   // branch — it is treated as repo-acting so it fails loudly at startup instead
   // of silently running without auth.
   func requiresRepositoryAccess(taskType agentlib.TaskType) bool {
   	switch taskType {
   	case prpkg.TaskTypeSecurityReview:
   		return true
   	case agentlib.TaskTypeHealthcheck, prpkg.TaskTypeBuildFix:
   		return false
   	default:
   		return true
   	}
   }
   ```

   Repo-acting is exactly `{security-review}`; non-repo-acting is exactly `{healthcheck, build-fix}`; everything else (including `""`) takes the stricter branch. A predicate written as `taskType != prpkg.TaskTypeBuildFix` is wrong — it lets `healthcheck` fail at startup. A predicate whose default is `false` is wrong — it lets an unknown type run unauthenticated. Neither set is configurable.

   ```go
   // task_type defaults to the security-review route — this binary is the
   // security agent.

   }
   ```

3. **Add `prepareTaskAuth`** to `cmd/run-task/main.go` — the method that embodies the required order: read the task file → derive the task type from its content → resolve credentials only for a repo-acting type → dispatch. `Run` calls this and nothing else in this sequence.

   ```go
   // prepareTaskAuth reads the task file, derives the task type from its
   // frontmatter, resolves GitHub App credentials only when that type acts on a
   // repository, and dispatches the matching agent.
   //
   // The order is load-bearing: this binary has no TaskType config field, so the
   // task type is unknown until the task content has been parsed. Resolving
   // credentials before that parse is the defect this method exists to prevent.
   //
   // Returns the raw task content, the resolved installation token (empty for a
   // non-repo-acting type) and the dispatched agent.
   func (a *application) prepareTaskAuth(
   	ctx context.Context,
   	repoAllowlist []string,
   	reposPath string,
   	workPath string,
   ) (string, string, *agentlib.Agent, error) {
   	taskContent, err := os.ReadFile(
   		a.TaskFilePath,
   	) // #nosec G304 -- filePath from trusted CLI input
   	if err != nil {
   		return "", "", nil, errors.Wrapf(ctx, err, "read task file: %s", a.TaskFilePath)
   	}
   	taskType, err := parseTaskType(ctx, string(taskContent))
   	if err != nil {
   		return "", "", nil, err
   	}
   	var resolvedToken string
   	if requiresRepositoryAccess(taskType) {
   		resolvedToken, err = a.resolveAuth(ctx)
   		if err != nil {
   			return "", "", nil, err
   		}
   	} else {
   		glog.V(2).Infof(
   			"task-type %q does not require repository access — skipping GitHub App auth",
   			taskType,
   		)
   	}
   	agent, err := a.dispatchAgent(
   		ctx,
   		string(taskContent),
   		repoAllowlist,
   		resolvedToken,
   		reposPath,
   		workPath,
   	)
   	if err != nil {
   		return "", "", nil, errors.Wrap(ctx, err, "task type dispatch")
   	}
   	return string(taskContent), resolvedToken, agent, nil
   }
   ```

   `resolveAuth` is unchanged: unexported, same signature, same error text, same `useGitHubApp` computation. Do not widen it to take a task type — the reordering belongs in `Run`, not in the signature.
